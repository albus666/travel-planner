## 当前架构

```mermaid
flowchart TD
  DATA[采集、清洗、主题切块] --> PG[(PostgreSQL / pgvector)]
  EMB[BGE-M3 向量化] --> PG
  API[FastAPI / SSH 隧道] --> SEARCH[/search]
  SEARCH --> RET[BGE-M3 查询编码与纯向量检索]
  RET --> PG
  API --> ASK[/ask]
  ASK --> GRAPH[LangGraph：现有规则与语义路由计划]
  GRAPH --> SQL[按需只读 ticket_raw SQL]
  GRAPH --> RET
  SQL --> PG
  GRAPH --> ANS[DeepSeek 回答、引用校验、分段合并]
  API --> PLAN[/plan：独立开关]
  PLAN --> COLLECT[收集条件 / 必要时追问]
  COLLECT --> POOL[固定七景点目录筛选]
  POOL --> PG
  POOL --> RET
  RET --> DRAFT[原文依据、草案约束校验]
  DRAFT --> RESULT[候选顺序与引用 / 明确待确认项]
```

图为能力调用关系；/plan 使用固定流程和原文证据，不使用 LLM planner。/ask 单路径跳过无关工具，混合需求分别保留 SQL 与 RAG 状态；/search 不经过规划图。

## 规划 v1 边界

仅洛阳一日游，固定七个完整名称：龙门石窟、天子驾六博物馆、洛阳博物馆、隋唐洛阳城应天门遗址、隋唐城遗址植物园、王城公园、从政坊游园。不代表全市候选覆盖。

收集日期、出发地、同行人、偏好、节奏、交通方式；支持必去/排除与歧义追问。步行最多 1 站、轻松最多 2 站、其余最多 3 站。顺序依据必去、出发地同名、偏好得分及 POI ID，不是地理优化。

`arrival_time`、`visit_duration_minutes`、`travel_minutes` 恒为 null 是设计决定。没有地图/天气，不承诺实际交通、精确时间表、实时开放或一天内可行。启用配置 `RAG_PLANNING_ENABLED=1`。服务保持私有监听 `127.0.0.1:8100`。

## 距离完整 RAG Agent 的缺口

1. 现有规划是受限草案；尚无地图路线、天气、实时票价或开闭园工具，未验证交通可行性。
2. 已有确定性上限和证据检查；尚无通用规划、执行反馈、自动补查与重规划循环。
3. 尚无服务端持久化多轮会话；澄清后由客户端提交完整字段。
4. 实体别名、父子 POI、跨景点复杂需求、增量更新与过期数据治理仍待完善；源数据仍未权威核实。
5. 缺真实用户独立评测、生产级鉴权/限流、负载与成本/调用链验收。

旧规划应用已按用户要求删除；当前问答图与规划图是新实现，未恢复旧应用。详见 `docs/LEGACY_PLANNER_REMOVAL.json`。

今后新能力先固定评分维度，再整批评审；评审只记录 issue，结束后一次决定接受、暂缓或修复。不通过同样可以结束一轮，不自动进入反复修改。
