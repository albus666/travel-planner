# 洛阳一日游：有证据的候选草案

新增独立 `/plan`，不扩展 `/ask` 路由。`RAG_PLANNING_ENABLED=1`启用，0并重启关闭；原问答和/search保持原路径。使用已有BGE-M3、固定只读候选目录查询、原search和来源/引用校验，不调用LLM planner、地图或天气服务。

## 输入与追问

支持日期、出发地、同行人、偏好、节奏、交通方式。缺少这些条件、日期已过去、出发地仅写“酒店”等模糊值时，返回needs_clarification和questions；补齐同一请求字段后再次提交。暂不持久化多轮会话。

自然文本可提取常见明确表达，例如“明天从洛阳站出发，带爸妈，喜欢历史文化，慢节奏，打车去洛阳一日游”。相对日期按北京时间计算；复杂表达请使用结构化字段，不宣称完整自然语言理解。

```json
{
  "request": "给我安排洛阳一日游",
  "city": "洛阳",
  "days": 1,
  "trip_date": "2026-10-16",
  "departure": "洛阳站",
  "companions": "两位成人",
  "preferences": ["历史文化"],
  "pace": "适中",
  "transport": "公共交通",
  "must_visit": ["龙门石窟"],
  "avoid": ["洛阳博物馆"]
}
```

日期替换为实际计划日期。偏好支持历史文化、博物馆、园林、自然风光、亲子或不限；节奏为轻松/适中/紧凑，交通为公共交通/出租车/自驾/步行，常见同义词可归一化。

必去和排除用完整景点名称。显式“必去某景点/不去某景点”的常见文本也会保留；简称或未覆盖景点先追问，不自动匹配相似景点。必去/排除冲突、必去数量超过上限时追问。未支持的结构化字段拒绝接收；检测到预算、轮椅或精确耗时等未可核实硬约束时，先请求放宽为待确认项，不声称满足。

## 候选与证据

第一版候选池限定为数据库中实际收录的七个全名：龙门石窟、天子驾六博物馆、洛阳博物馆、隋唐洛阳城应天门遗址、隋唐城遗址植物园、王城公园、从政坊游园。这是有意限定的人工候选池，不代表检索覆盖全市，也不推断它们相互距离。

LangGraph流程为：收集→读候选目录→检索证据→草案/约束校验→返回。目录查询固定参数、只读事务；每景点复用search取Top5，仅使用该poi_id的介绍、历史或游览主题。偏好相关性由所引用正文中的明确关键词筛选，保留必去要求；不是语义最优推荐保证。

每个景点选择依据直接引用连续原文，保留来源URL和采集时间。只引用真正属于该景点的片段。没有支持偏好的证据不推荐为匹配候选；必去景点缺证据时不输出“已满足全部要求”的行程。检索失败和没有证据分别记query_failed、queried_no_evidence；没有执行记not_queried。

轻松最多2站，适中/紧凑最多3站，全程步行最多1站；这些是草案规模上限，不是可行性估算。顺序按必去、字面出发点名称和偏好组织，不是最短路线或交通优化。出发地恰为候选景点的全名时可优先该景点，但不推断距离。

## 草案与待确认项

返回status=draft、stops、selection_basis、citations和sequence_status=draft_unverified。景点数据支持选择依据，顺序安排只是建议。arrival_time、visit_duration_minutes与travel_minutes均为null；跨景点legs为not_queried。没有交通耗时或实时开放保证。

指定日期开放、预约、活动、实时票价、出发点位置、景点之间路程未核实。同行老人或儿童有明确适用性限制说明，不从简介推断无障碍或亲子安全。某部分缺资料会保留已取得证据，并说明限制；没有足够资料时返回insufficient_evidence。
