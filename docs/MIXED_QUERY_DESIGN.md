# 混合问题：设计与实施范围

依据30题用户评审，原单路径版本作为基线继续冻结。本文件最初定义实施前边界和验收；当前实施范围以新增里程碑记录为准。不增加LLM分类兜底或恢复LangGraph。

后续实施记录：最小显式复合句支持已部署，详见 `docs/MIXED_QUERY_MILESTONE_2026-10-12.md`。本文保留设计依据；多景点、任意自然语言拆解和自主反馈循环仍未实现。

## 处理流程

1. 将用户请求表示为多个明确的需求项，每项记录景点、所需store和能力限制。票价原文指向ticket_raw，优待/路线/历史/设施指向RAG；不能把出现RAG主题当作放弃价格需求的理由。
2. 单store问题继续调用冻结的现有路径。混合问题的新执行器单独开关，默认关闭，避免影响现有单路径基线。
3. 校验实体后执行受限工具。SQL只允许既有参数化只读票价查询；文本仍沿用现有向量排序。不能把用户文字或模型输出拼接成SQL。
4. 混合问题取回ticket_raw和文本证据，分别保留来源、采集时间、适用景点、主题和工具状态。证据ID全局唯一，SQL原文与文本片段都可引用。
5. 合并回答按用户需求逐项作答，价格优先保留原始值；不得用优待文案代替ticket_raw。每一项标注已答、证据不足、未执行或不支持，最后校验需求覆盖与引用。

“某工具未查”“某路径没有”“某字段为空”“所有可用资料均无证据”是不同状态。只运行RAG时，最多说明“所提供片段没有票价”；没有检查SQL字段，不能断言整个资料库没有票价。已查询到价格快照也不能确认实时价格或特定票种成交价。

## 实体与错误提示

- 名称缺失：请求景点名称。
- 已给名称但目录无匹配（第25题）：说明现有目录未找到该名称，可请用户核对；不要仅重复要求“提供完整名称”，不要虚构匹配。
- 别名或歧义：请求明确景点，不自动把“龙门”映射为龙门石窟。
- 多景点查询（第26题）：第一版明确说明一次只支持单景点，并请求拆分；若未来支持多实体，需要另行评测，不能沿用单景点未解析提示。

## 验收

- 27—30题应执行两路，或在工具不可用时明确指出未完成的需求。正常情况下必须返回数据库已存在的票价原文。
- 29题轮椅证据不足仍需明确无法确认，同时完整回答票价原文。
- 25、26题分别检查未收录名称提示与单景点能力提示，不能只以“拒答”状态算通过。
- 检查SQL故障、RAG故障、价格字段空值、文本证据缺失时的部分成功与原因提示。
- 启用实验后重跑原25题、73题、58题及30题；分类指标、工具调用与答案质量分别统计，混合题要求所有需求覆盖。
- 第20题停车费单位不明属于数据项，保留原文与单位不明提示，不推断元/次或元/小时。

先落实需求列表、两个受限工具和覆盖校验即可验证上述改进；待其稳定，再决定是否用LangGraph承载执行状态。
