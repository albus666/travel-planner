# LangGraph最小工具契约

M1—M4最小工具图已接入，实施与回归结果见 `docs/LANGGRAPH_MILESTONE_2026-10-12.md`。下文保留契约依据；没有通用LLM planner或行程规划。

以用户验收的mixed v1为行为基线。先把现有检索与门票查询接为边界明确的工具，保留现有分类和拆分逻辑；不恢复旧行程规划，不增加LLM分类，不开放任意SQL。

## 工具输入输出

| 工具 | 输入 | 输出与限制 |
|---|---|---|
| ticket_sql | 价格子问题、用于实体定位的完整原问题 | ticket_raw原文、景点、来源/采集时间、SQL1引用、实体解析结果、实际字段查询是否执行；复用try_ticket_answer和原固定参数SQL |
| retrieve_chunks | 单独文本子问题、top_k；同请求已有向量可复用 | 原search命中列表，顺序不变；仅返回候选片段，不把命中数直接当作答案证据 |

文本回答生成仍是独立步骤，复用answer_question的原文引用校验。SQL价格段保留现有模板，不交给模型重新改写数值。模型或用户不能传入SQL字符串、表名或任意过滤条件。

## 最小流程

请求 → 计划 → 按需求执行ticket_sql → 按需求执行retrieve_chunks → 文本回答与引用校验 → 合并。

计划沿用现有规则/语义路由和显式混合拆分，产出required_stores与子问题。单路径跳过不需要的工具；混合路径先取得唯一景点与价格快照，再以景点名和文本子问题检索。实体歧义时请求澄清，不强行组合多个景点。

流程状态保留原问题、子任务、required_stores、各工具结果、逐项取证状态、answer_status、引用与警告。最初不启用多轮持久化，不把密钥、数据库连接或模型实例写入状态。

最终子任务状态保持not_queried、query_failed、queried_no_evidence、queried_with_evidence四种。retrieve_chunks返回候选不等于有支持该需求的证据；最终取证状态需要结合引用校验后的回答确定。第29题即使retrieved_count大于0，轮椅子任务仍可queried_no_evidence。

## 接入验收

1. 先用独立开关接入，开关关闭时完全复用当前/ask；/search不经过新流程。
2. 工具使用输入输出契约，记录每个计划任务是否执行；SQL/RAG一方失败保留另一方结果。
3. 对冻结的27—30题检查价格原文、文本要点、对应引用与部分拒答；生成答案不能照搬旧人工分数。
4. 重跑30/25/73基线，比较单路径/上下文、SQL原文和/search顺序；分别记录工具调度与答案质量。
5. 这一阶段只接入流程与两个已有工具；通用自主规划、补查循环、多景点、多轮和行程校验留待另行实现。
